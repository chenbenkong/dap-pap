## 📖 这是什么？

这是一个面向**科普教育**的交互式 3D 教具。它把一枚通用战术导弹放进同一座实验台里，让你沿着一条完整的认知主线走完：

> **先看它是什么做的 → 再看它怎么产生推力 → 最后跟它飞完全程打中目标**

没有割裂的"第 1 章 / 第 2 章"，只有**同一枚导弹在同一个实验台上的三个工位**。切换工位时相机是"走过去"的，不是瞬移——你始终知道自己在看同一件东西。

| 工位 | 回答的问题 | 你可以做什么 |
| :---: | :--- | :--- |
| 🧩 **装配台**<br>`ASSEMBLY` | 这枚导弹是什么做的？ | 拉爆炸滑杆拆成 8 大舱段、开剖视看内构、点任意部件查档案 |
| 🔥 **试车台**<br>`TEST BENCH` | 它怎么产生推力？ | 点火试车、拖药柱燃面滑杆看星型装药退移、读推力/流量曲线 |
| 🎯 **靶场**<br>`RANGE` | 它怎么飞过去并命中？ | 一键发射，从助推飞到命中；末段自动画出视线连线与预测命中点 |

整个项目**零外部资源依赖**：没有加载任何 3D 模型文件、贴图文件——导弹的每一颗铆钉、每一段舱缝、每一块喷涂标识，全部由代码程序化生成。

## ✨ 功能特性

### 🧩 装配台 · 结构解剖
- **8 大舱段**：天线罩 / 导引头位标器 / 战斗部舱 / 近炸引信环 / 制导控制舱 / 固体火箭发动机 / 喷管组件 / 空气舵×4
- **爆炸视图滑杆**：0~100% 连续控制拆装动画，每个舱段沿装配轴分离；**相机随拆解度自动后撤**，散得再开也不会飞出画幅
- **装配关系能量线**：拆解时相邻舱段之间拉出发光连线，一眼看出"谁装在谁上面"——没有它，散开的部件只是一堆悬浮零件
- **点击部件 → 自动飞到特写**：相机平滑推近到该部件，特写距离按部件实际尺寸自适应——小到引信环、大到发动机，都刚好占满画面
- **剖视内构**：基于裁剪平面（clipping plane）的实时剖切，露出内部件——万向支架上的导引头天线、预制破片环、电路板组、IMU、点火器、星型药柱……
- **部件档案**：点击 3D 部件或左侧卡片，右侧面板同步展示该部件的作用说明 + 技术参数表 + 深度解读
- **3D 标注**：跟随视角浮动的中文/英文双语部件标签，带引线锚点
- **高亮开关（部件自发光）**：装配台 / 试车台各有一个 `高亮部件` 开关，默认关。打开后**点击哪个、只高亮哪个**（不累计、不残留）。高亮是让该部件**自发光**——在材质本色基础上透出一层冷白光，强度压得很低（0.3），只让选中件"透"一点光、一眼能分辨，**不会盖住蒙皮、铆钉与喷印细节**。
  - 实现前提：多个舱段原本**共用同一批材质实例**（如 `steel` 被几乎全部舱段复用），直接改 `emissive` 会让所有共用件一起亮。因此 `parts.ts` 在注册部件时给每个舱段**克隆了独立材质**，并据此重建 `shellMats` / `allMats`，保证剖视裁剪仍然生效。

#### 科幻细节层
整机视图下弹体只有几十像素宽，这些细节是给**特写**和**拆解视图**准备的——镜头推近后才会真正被看见。

外观走"未来 50 年"的科幻方向（**AURORA-7 动能拦截弹**）：深空灰蓝隐身涂层、青蓝能量色带、等离子喷口环，机体上喷印的是科幻铭文（`KINETIC INTERCEPTOR · MK.VII`、`PLASMA BUS ACCESS`、`MFR-7 WARHEAD`），不是军械厂的黄标——把它当成"将来可能存在的导弹"来做：

- **能量导管**：制导舱蒙皮里嵌着四条**青蓝自发光**导管，两端用集束箍收口
- **等离子喷口环**：喷管出口两道高能青环，灼烧感直接写在嘴上
- **黄黑警示环带**：战斗部外缘的斜纹警示带，用薄片拼出体积感而非贴图
- **外部推进剂管路**：发动机舱两侧一送一回两条管路，沿途四道卡箍
- **散热沟槽**：沿弹体密布的细环槽，近看才有的一层层次
- **拆解特效**：拉爆炸滑杆时，部件沿装配轴分离 + **呼吸式能量连线** + 地面**全息能量环**随拆解度扩张

### 🔥 试车台 · 动力原理
- 点火试车：推力曲线实时绘制，**程序化体积火焰**（自定义 GLSL + FBM 湍流噪声 + 视线厚度近似）+ 火花粒子 + 动态点光源
- **装药燃面滑杆**：手动控制药柱燃烧进程，星型内燃药柱几何体实时重建——直观理解"燃面 → 推力"的关系
- 遥测面板：即时推力（kN）、燃气流量（kg/s）、燃尽时间
- 三段式羽流：外层火焰 / 内层焰心 / 白炽核心分别滚动，形成真实的湍流层次
- 点火爆燃、燃烧轰鸣、熄火——音效跟着推力曲线走（见下方音效章节）

### 🎯 靶场 · 一次发射走完整条时间轴

原来的"追击演示"和"弹道演示"是两个各说各话的 demo，现在合并成**一次发射的完整时间轴**：

```
点火 → 助推 BOOST → 惯性中段 MIDCOURSE → 末段导引 TERMINAL → 命中 IMPACT
```

- **指数大气模型**（密度随高度衰减）+ 音速近似下的完整弹道积分，预积分后时间轴可任意拖动回放
- **真实目标舰**：舰船按"命中时刻恰好位于命中点"反解运动，所以你看到的拦截不是摆拍——开不开"目标机动"，导弹都得重新算
- **末段导引可视化**：进入末段自动绘制
  - 🔵 **视线连线（LOS）**——导弹与目标之间的视线，这是比例导引律的输入
  - 🎯 **预测命中点光环**——按当前相对运动解出的提前量拦截点
  - 📊 实时读数：剩余距离 / 接近速度 / 需求过载
  - 📊 实时读数：剩余距离 / 接近速度 / 需求过载
- **飞行 HUD**：阶段、T+ 时间、高度、速度、马赫数、过载、已飞距离、脱靶量，随任务实时刷新
- 命中判定 + 爆炸特效（火球 + 冲击波 + 破片）

### 🎥 五种机位 · 发射后可随时切换

| 机位 | 距离 | 适合看什么 |
|---|---|---|
| **第一人称** `FPV` | 贴弹 | 骑在弹背上，视点盯住弹身前段，弹体占满画面下半部 + 速度感 FOV 随马赫张开 |
| **第三人称** `CHASE` | 57–69 m | 侧后方约 33° 跟拍，弹体以**侧影**入画（占画面 40%~85%），末段视线自动压向目标舰 |
| **电影机位** `CINE` | 72–88 m | 侧后方 36°~84° 缓慢环绕，看清扫全貌与弹目相对位置（占画面 29%~68%） |
| **全局** `GLOBAL` | 战区尺度 | 更快的低空环绕，俯瞰完整弹道，菱形光标标出导弹位置 |
| **自由** `FREE` | 交还鼠标 | 自己拖着看，适合观察爆炸与目标舰 |

跟拍机位由本模块直接驱动相机（绕开 OrbitControls，否则 `controls.update()` 会用 target 反推球坐标、把手动设置的机位改写回去）。**想自己转镜头？跟拍中直接在画面上按住拖动，立即交还 OrbitControls（自动切"自由"），点机位按钮即可回到自动跟拍。**

几个坑已经填掉，都是实测出来的：

1. **发射瞬间相机钻到地下** —— 旧实现沿"-速度方向"偏移，而发射时程序角 72°，相机被甩到 y ≈ −52 m。现在改用**水平后方向 + 世界上方**偏移，并给相机地面高度兜底。
2. **助推段导弹掉出画面下缘** —— 视线原本指向"弹前方 34 m"，但爬升时速度方向上仰 60°~70°，前方几十米处远高于弹体，相机随之仰头，实测夹角 22.4° 已超过垂直半视角 21°，导弹整个出画。现在视线沿**水平前方**引导并略微上抬，弹体稳定落在画面中心偏下。
3. **跟拍平滑追不上超声速（最严重）** —— 指数平滑的稳态滞后 ≈ **速度 / 响应系数**：约 1000 m/s、resp 4.2 时相机被甩在弹后 **200+ 米**，弹体又小又飘、爬升时直接飞出画面上缘；视点滞后更致命，相机等于回头看。修法是**在弹体局部做平滑**：把目标机位换算成"相对弹体的偏移量"，只对偏移量插值再挂回弹体当前位置——保留电影感缓动，但对弹体**零滞后**。
4. **正对弹尾，只能看见尾部一个圆截面** —— 第三人称原来挂在纯"水平后方向"上，等于从正后方看导弹，细长弹体被自己完全挡住。现在固定偏到侧后方约 33°；电影机位的环绕范围也从 0.62±0.85 rad 收成 1.05±0.42 rad，避免摆回 0 又变成正对弹尾（实测那一瞬间弹体只剩画面 11%）。
5. **命中后黑屏 + 卡死** —— 命中后 `tickRange` 直接 return，相机冻在最后一帧，而跟拍机位此刻正在 **130 m 火球内部**，画面糊成一片黑；随后任何一帧抛异常都会让 `requestAnimationFrame` 断掉，整个应用永久卡死。现在：命中后切**战后环绕机位**（退到火球外 640 m 缓慢环绕）、主循环把 `rAF` 排在最前面并对每个子系统做异常隔离。

### 🎯 无头相机审计

相机这类"看不看得到"的问题，光靠截图验证不了（headless 下 rAF 不推进）。`npm run auditcam` 把机位数学原样搬到 Node 里，拿真实弹道采样逐点验算并断言 5 项：

```
✓ 全弹道弹体中心始终在画面内
✓ 跟拍机位不正对弹尾（能看见弹体侧影而非尾部圆面）
✓ 跟拍距离在特写量级（< 260 m，不会被甩开）
✓ 相机全程不钻地
✓ 弹体在画面中占比 ≥ 25%（是特写而不是小点）
```

会打印每个机位在各时刻的**距弹距离 / 画面占比 / 视线与弹轴夹角 / 是否在画面内 / 离地高度**。第三条（不正对弹尾）正是为上面第 4 个坑写的回归测试——它当时能稳定复现失败。

| 点火爆燃 | 噪声爆发 + 低通扫频 + 锯齿波上行 |

## 🧠 核心技术亮点

### 1. 零资源程序化建模
不加载任何模型/贴图文件，导弹完全由代码"长"出来：

- **PBR 程序化蒙皮**：Canvas 生成 1024×2048 反照率图 + 512×1024 粗糙度图 + 金属度图 + 高度→法线图；覆盖舱段缝/双排铆钉/检修盖板/NO STEP / LIFT HERE 喷涂/漆面剥落露裸金属/尾部烟熏/磨损流痕；UV 沿弹体全局坐标映射，8 个舱段爆炸分离后漆面依然连续
- **真实气动外形**：切线卵形（tangent ogive）头部曲线、船尾收锥、拉瓦尔喷管（Catmull-Rom 样条平滑轮廓）、**沿展向放样的真实翼型弹翼**（弦长/厚度收缩、前缘后掠）+ 翼尖滚转舵（rolleron）
- **能烧的药柱**：8 角星型内燃装药截面，燃烧时几何体按燃面退移规律实时重建

近距离看蒙皮——舱段缝、双排铆钉、检修盖板、漆面剥落露出的裸金属，全部是 Canvas 画出来的，不是贴图文件：

### 2. 简化但严谨的飞行物理
- 指数大气密度模型 `ρ(h) = 1.225·e^(−h/8500)`（国际标准大气近似）
- 音速近似 `a(h) ≈ 340 − 0.0038h`
- 比例导引律 `a = N·Vc·λ̇`，视线角速率由 `ω = (r × ṙ)/|r|²` 解出（正是装配台里"导引头位标器"讲解的核心量，前后呼应）
- 全弹道数值积分，助推/中段/末段按质量与推力状态自动切换
- **过载严格区分轴向与横向**：助推段报告弹体轴向载荷（约 16 G，真实战术导弹同量级），末段报告垂直于速度的机动过载（受气动舵能力 `nMax` 约束，满舵 12 G）。二者物理含义不同，不能混为一谈——这点第一个版本就算错过，是无头自检抓出来的

### 3. 物理层可被自动验证
3D 效果好不好看，截图说了算；物理对不对，得靠断言。`tools/selftest.mjs` 用 esbuild 把 `flight.ts` 打进 Node，不开浏览器跑完整任务，断言 26 项：

```bash
npm run selftest
```

### 4. 剖视 = 材质级裁剪
剖视内构不是"把壳变透明"，而是用 `WebGLRenderer.localClippingEnabled` + 裁剪平面只切外壳材质——切口干净、内部件完整、帧率无感。

## 🚀 快速开始

```bash
# 1. 克隆
git clone https://github.com/chenbenkong/dap-pap.git
cd dap-pap

# 2. 安装依赖（需要 Node.js ≥ 18）
npm install

# 3. 开发模式（热更新）
npm run dev

# 4. 生产构建 + 本地预览
npm run build
npm run preview
```

浏览器打开终端里显示的地址即可。推荐使用最新版 Chrome / Edge / Firefox。

### 可用脚本

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发服务器（热更新） |
| `npm run build` | 生产构建到 `dist/` |
| `npm run preview` | 本地预览构建产物 |
| `npm run typecheck` | TypeScript 类型检查 |
| `npm run selftest` | 无头物理自检（不开浏览器，约 2 秒） |
| `npm run verify` | 类型检查 + 物理自检 + 构建，一条龙 |

## ☁️ 部署你自己的实例

1. **Fork** 本仓库
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**
3. （如果改了仓库名）同步修改 `vite.config.ts` 里的 `base: '/dap-pap/'`
4. push 任意提交 → Actions 自动构建并发布

## 🎨 二次开发指南

| 想做什么 | 改哪里 |
|---|---|
| 换涂装配色 | `src/parts.ts` → `makeBodyMaps()` 底色 / 喷涂文字 |
| 加/改部件 | `src/parts.ts` → `buildMissile()` 内新增组，再 `reg()` 注册（文案与锚点一并填） |
| 加科幻细节 | `src/parts.ts` → `addSciFiDetails()`，用 `spanOf()` 自动适配舱段尺寸 |
| 调发动机参数 | `src/parts.ts` 药柱尺寸 / `src/main.ts` 推力曲线 |
| 调弹道/导引律 | `src/flight.ts` → `StrikeSim` / `MissionSim`，改完跑 `npm run selftest` |
| 调跟拍机位 | `src/main.ts` → `CAM_PRESET`（距离/高度/前瞻/FOV/响应） |
| 加音效 | `src/audio.ts` → `Sfx` 类，按现有合成风格追加方法 |
| 飞行中弹体大小 | `src/main.ts` → `MISSILE_WORLD_SCALE`（当前 4.0，仅影响靶场） |
| 加/改工位 | `src/main.ts` → `STATIONS` 与 `STATION_ORDER`，同步在 `index.html` 加按钮与面板分组 |
| 改工位相机机位 | `src/main.ts` → `STATIONS[key].cam` / `.tgt`，或 `updateStationCam()` |
| 调全流程演示节奏 | `src/main.ts` → `runFullShow()` 的各步延时 |
| 加物理断言 | `tools/selftest.mjs`，按现有 `ok(cond, label, extra)` 风格追加 |
| 回归跟拍质量 | 打开 `#audit=1,5,20,50,68&auditCam=chase,fpv`，看隐藏的 `#camAudit` |
| 关闭辉光后期 | `src/scene.ts` → `bloomPass.enabled = false` |
